About

Compliance Tooling That Closes the Gaps

Most compliance tools give you a score and leave the work to you. Darnit runs the checks, gathers the project context it needs, drafts the fixes, and produces a signed attestation you can hand to users, foundations, or auditors. Compliance becomes a step you run, not a spreadsheet you fill in.

Security is a key focus, but the checks go further: testing practices, build reproducibility, project governance, licensing, and documentation. Each standard is a plugin, and the OpenSSF Baseline plugin ships in the box.

How It Works

Audit, Confirm, Remediate, Attest

Darnit works through a project in four steps. Nothing on the repository or the platform changes without your approval.

  1. 01

    Audit

    Each control passes through the sieve: deterministic checks first, then pattern matching, then a question to your AI assistant, and finally manual verification. A control passes only when a check proves it.

  2. 02

    Confirm Context

    Darnit never guesses facts that only you can know, such as maintainers or security contacts. It asks you, records your answers in .project/, and re-audits.

  3. 03

    Remediate

    Fixes are previewed by default, and only the changes you approve are applied. Platform settings are only ever tightened, never weakened. Darnit then opens a branch and a pull request with the files it wrote.

  4. 04

    Attest

    The result is an in-toto attestation signed with Sigstore, so anyone can verify your compliance claims without trusting a screenshot.

Conservative by default: a result of WARN means “we don’t know yet” and counts as not passing. A wrong pass is worse than an honest gap.

Features

Built to Be Extended

Plugin Architecture

Implement any compliance standard as a Darnit plugin, with controls declared in TOML.

Compose in TOML

Combine slices of the plugins you have installed into your organization’s own posture, with no forking and no Python.

Agent-Native

An MCP server and ready-made skills let Claude Code and other agents audit and fix your project in conversation.

Safe Remediation

Dry run by default, approval tied to the exact change, and settings that are only ever tightened.

Signed Attestations

in-toto statements signed with Sigstore. Plugins are signed and verified too.

CEL Pass Logic

Pass conditions are written in CEL, so they are readable and easy to review.

Project Context

A single .project.yaml records where your docs and policies live and what you have confirmed.

STRIDE Threat Model alpha

Drafts a starting threat model, best for Python web services and MCP servers.

Your Standard, Without a Fork

Need “Baseline levels 1–2, every gittuf check, and one rule of our own”? Write it as a composition in TOML. Darnit resolves it when it loads, and the controls you pull in stay up to date with their upstream plugins.

Composition quickstart → 

# acme-baseline.toml
[[compose]]
source           = "openssf-baseline"
include_levels   = [1, 2]
exclude_controls = ["OSPS-AC-02.01"]

[[compose]]
source      = "darnit-gittuf"
include_all = true

[controls."ACME-DEPLOY-01.01"]
name  = "DeployWindowEnforced"
level = 1
OpenSSF Baseline

What Darnit Checks Out of the Box

The bundled OpenSSF Baseline implementation (OSPS v2026.02.19) covers 62 controls across eight categories and three maturity levels.

OSPS-AC

Access Control

Branch protection, MFA, and least-privilege permissions on repos and CI.

OSPS-BR

Build & Release

Signed artifacts, pinned dependencies, and sound release processes.

OSPS-DO

Documentation

READMEs, changelogs, and support information users can rely on.

OSPS-GV

Governance

Maintainer documentation, contribution guidelines, and response expectations.

OSPS-LE

Legal

Clear, consistent licensing and contributor agreements (DCO or CLA).

OSPS-QA

Quality

Code review requirements, CI/CD quality gates, testing, and static analysis.

OSPS-SA

Security Architecture

Threat modeling and a secure-by-design posture for the codebase.

OSPS-VM

Vulnerability Management

Security policies, dependency scanning, and timely response to advisories.

The Baseline is the first of several plugins. The repository also ships reproducibility checks, gittuf policy checks, and Community Specification License checks. To write your own, start from the plugin packaging guide.

Get Started

Up and Running in Two Commands

1 Install

$ uv tool install git+{{ $repo }}

Requires Python 3.11+ and uv. To try it without installing, run uvx --from git+{{ $repo }} darnit audit .. A PyPI release that installs the darnit command is coming next, and Homebrew and container images are on the way.

2 Connect Your Agent

$ darnit install         # MCP config + skills
# restart Claude Code, then:
> /darnit-audit

The skill runs the audit, asks about anything it can’t safely guess, previews fixes, and generates the attestation. It works with Claude Code, Claude Desktop, and Cursor; see using skills.

Just want to see a report in your terminal? 
$ darnit audit /path/to/repo

The CLI is handy for a quick check or for iterating on controls. Remediation and attestation work best through the agent workflow above.
